# Bulk filing

Many linked issues from one manifest: a spec split, a review's findings, a migrated workset. When verified findings already exist, file from them; read a saved audit workflow's script before running it, since it may redo the whole audit.

- **Look for a sibling session on the same source** before drafting (`ListAgents`, scratch folders such as `/tmp/*issues*`). List issues created since your snapshot again right before and right after the create pass, and close later duplicates (naming the in-flight copy) before any `ready` swap.

- **One Python script file** drives create, fill, link and verify. Harness auto mode and worktree sessions refuse compound shell `gh` commands (GraphQL with braces, heredocs, `&&` chains). Call `subprocess` with `stdin=subprocess.DEVNULL`, because a `gh` call in a loop otherwise eats the loop's input. Pop `GH_TOKEN` from the env. Retry a `gh` call up to 5 times with backoff when stderr matches a timeout, "Something went wrong", 502 or 503; stop at any other failure, so a later step never reports an earlier one as done.
- **Drafting 40+ bodies:** fork the drafting by section, with one shared brief file naming every key, its ids and planned deps, the shared `## Notes` paragraph, a distinct route anchor per group, and the pages other groups rewrite. Record in the brief the spec commit and base SHA the drafters read. Drafting finds spec cells wrong against the code: fold those corrections into the spec in the same PR as its Issues table, after checking that PR is still open (`gh pr view N --json state`); a merged one needs a new branch from main.
- **Review every agent-drafted body before filing** with a separate reviewer given the gate facts (database in the gate versus CI, pinned static-analysis baselines, a patch-coverage gate). Have it judge each same-file pair of drafts as `chain` or `apart`; most pairs need no link.
- **Splitting a spec whose issues are h2 blocks with h3/h4 inside:** demote `### ` to `## ` before `#### ` to `### `, or the h4 sections land as h2 and the factory sees extra top-level headings.
- **Before creating:** the spec and base can move while forks draft. Ground drafters and fixers on `git archive origin/main | tar -x` in a scratch folder at a recorded sha, and add one Notes line to every body: line numbers were read at that sha, find the place by the quoted text, stop needs-info if the text is gone. When a large PR opens meanwhile, hold at `factory:proposed` only the issues whose edited source it rewrites. Diff the recorded spec commit against the branch tip (`git log <sha>..<branch> -- <spec>`) and re-draft every changed row. Run `git diff --stat <drafting sha> origin/main`, grep the bodies for every changed file, and chain each hit behind the open sibling issue that still edits it, scoping the body to the new code path in one criterion. A mismatch found after filing: park the unclaimed issue at `factory:proposed`, then fix it. Check every manifest key has a non-empty body file. For a spec split, collect every active requirement ID in the spec, expand ranges such as `X-001 to X-011` in the issue texts, and list any ID no issue names.
- **Create every issue first,** in dependency-layer order, and in priority order within a layer: the factory claims ready issues by number, so creation order is build order and the order of the `ready` swaps changes nothing. Manifest titles carry the `<type>: ` prefix, and each create passes its `type:<type>` label. Bodies name siblings as `{{KEY}}`. Write `map.json` after each create so a rerun resumes. Siblings named in `## Notes` can form cycles, so a blockers-first create order cannot fill them.
- **Then one fill pass** substitutes the keys and runs `gh issue edit --body-file` only on bodies that held one. Match only manifest keys, with digits allowed (`[A-Z0-9_]+`, or a key like `E2E_TAG` silently fails), since a body may quote `{{PLACEHOLDER}}` or `${{ github.… }}`. Strip braces when the deps column holds `{{KEY}}`. `owner/repo#{{KEY}}` fills to `owner/repo#N` with no second `#`. Read a file into a variable before reopening it for writing: `open(p, "w")` truncates first, and the edit then pushes an empty body. Refuse to push an empty file.
- **Then link, then verify in one call:** an aliased GraphQL query (`i2: issue(number:2){…} i3: …`) returning `blockedBy`, `assignees.totalCount` and `body`. Compare the `#N` refs under `## Depends on` with `blockedBy`, and flag leftover keys and bodies with no `## Depends on` (a blank body). Keep the jq program in a file. Flip to `factory:ready` only after it reads clean.
